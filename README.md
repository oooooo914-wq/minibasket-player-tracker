# MiniBasket Player Tracker

AndroidのChromeで、スマートフォン内の試合動画から指定した1人を追跡するPWAです。
**現段階は選手追跡MVPです。走行距離・コート座標・正確な出場時間は計算しません。**

公開URL: https://oooooo914-wq.github.io/minibasket-player-tracker/

## MVP 0.5：早すぎるロストと原因不明への対応

利用者から、速い移動・密集・見え方の変化で頻繁に停止するとの報告がありました。コードでは、外見の確認が0.28秒途切れると停止し、補間の上限も0.8秒、似た候補の競合は即停止していました。また、画像追跡の移動を適用してから外見を確認していました。これらを変更しました。**実試合で改善した割合はまだ測定できていません。**

- 確認できない間は「予測保留」。初期設定は動画時間2秒、1／2／3秒から選択できます。画面に対象の予測枠と探索範囲を黄色の点線で表示。未確認期間は軌跡に加えず、復帰前後を線でつなぎません。保留時間は最終の人物検出確認から数え、Optical Flowだけで延長しません。
- 直近の確定位置から速度を早く学習。背景の平行移動を差し引き、Kalmanの予測速度・不確実さで探索範囲を調整します。Optical Flowの探索中心にも予測移動を使います。腕の開閉による枠幅の変化は、身長方向の変化より小さく評価します。
- 画像追跡が提案する移動先の外見を**移動を適用する前**に確認します。密集・遮蔽の保留中は局所フローを採用しません。選択時の色分布は固定アンカーとして保持します。
- 選手周辺の切り出しを保留時間・探索範囲に応じて拡大。0.4秒以上保留中は検出3回に1回を全画面探索に切り替えます。1回の検出につきAI推論1回で、二重推論はしません。
- 保留からの復帰には、外見・位置・候補間の差が条件を満たす**異なる時刻の3回連続確認（0.18秒以上）**が必要です。同じ停止画像の再検出は回数に入りません。
- 同じ外見の候補競合が0.25秒以上続いた場合は本人不明を保持します。後で候補が1人だけになっても自動で本人と認定せず、期限で停止して再指定を求めます。短い競合や区別できる服による遮蔽は、連続確認できれば復帰できます。停止後の自動復帰はありません。
- **「診断ログを保存」**でJSONを端末に保存できます。動画内時刻、推論時間、結果の遅れ、検出なし／位置差／外見差／枠の変化／候補競合／遮蔽などの判定、上位候補の枠・検出スコア・比較値・棄却条件、予測速度・探索範囲・背景移動を記録します。保存に対応しない環境では「診断ログを表示」から長押しでコピーできます。直近1,000件を保持し、件数集計は動画選択以降の判定フレーム数です。実際の失敗回数や正しい原因の確定ではありません。
- 診断には動画・画像・ファイル名・色分布そのものを含めず、自動送信もしません。問題直後に保存して共有すると、失敗直前の判定を調べられます。
- 青い枠の数字を「候補1」等と明記しました。**背番号ではなく、その停止画面の選択ボタンの番号です。背番号OCRは未実装です。** 追跡中の対象は「対象」と表示します。

## 解析速度への対応（0.4から継続）

初期設定は「精度優先（解析を待つ）」。動画は音声なしのコマ送りになり、1枚の解析結果を受け取ってから次へ進みます。CPUが遅くても動画だけ進んで結果が古くなることを防ぎます。

- 「精度優先」：動画時間で10〜15回/秒の画像サンプリング。人物検出設定は5〜10 fpsが上限で、サンプル間隔に量子化されます。実時間の処理速度は端末と動画のシーク性能に依存します。
- 「連続再生」：動画再生と並行して解析。音声あり。処理が遅すぎる場合は停止します。精度優先の速度設定は上限であり、重い場合はさらに遅く進みます。
- 対象未選択時は普通に再生できます。内部のコマ送りだけ追跡を維持し、ユーザーのシーク・動画変更は対象を破棄して古い結果を無効化します。
- 一時停止・選び直し・別アプリ移動・失敗時には自動送りを取り消します。

合計35テストが成功。予測保留と期限、速度学習、候補競合、連続復帰、診断履歴の上限と保存、2.5秒の推論遅延、同時処理1枚、内部／手動シーク、バックグラウンド、動画末尾、PWAのパスを模擬して確認しています。ブラウザの動画デコーダーや実試合の本人追跡精度を保証するテストではありません。

## 既存実装から継続する機能

既存のHTML / CSS / JavaScript / MediaPipe / canvas構成を継続しています。フレームワークへの置き換えや作り直しはしていません。

- ローカル動画をObject URLで開く。動画のアップロード・API課金・アカウント登録なし。
- 再生／停止、全体シーク、±1秒、±0.1秒、0.25／0.5／1倍再生。
- 一時停止中・時間移動後にも人物検出。枠タップまたは番号ボタンで1人を選択。
- キャンバスと再生操作を分離し、枠が再生ボタンを遮らないよう修正。
- 旧MediaPipe `0.10.22`のJS URLが404だったため、取得できる`0.10.21`へJS/WASMを揃えて固定。
- 初期画面の外部AI依存を外し、モデル読込に失敗しても動画UIを利用・再試行可能。
- AI専用のWebGLキャンバスを用意し、初回推論が成功してから「準備完了」を表示。
- 人物検出と軽量追跡をWeb Workerに移動。解析画像は長辺768px以下、同時処理は1枚、フレーム待ち行列なし。
- 人物検出5／7／10 fps（動画時間基準、上限）。画像追跡は実時間15 fps以下。重い端末では処理時間に応じて間引く。初期再生0.5倍、検出7 fps。
- 定速度Kalman Filter、予測位置、枠の大きさと重なり、胴体／パンツ別の色分布による外見比較。
- 背景および選手の小領域で疎なブロックOptical Flow。往復整合・中央値で不安定な移動を除外し、パン／手ブレの平行移動を補助。
- 選択時の外見を固定アンカーとして保持し、他人への段階的な特徴のずれを抑制。
- 許容時間を超える未確認、解消できない候補競合、処理遅延で停止。**見失い状態からは自動復帰せず、タップでの再指定が必要。**
- 緑の枠と足元マーカー、直近8秒の画面座標の軌跡。履歴は最大600点。
- 時間移動・動画変更では追跡を破棄。古いWorker応答を世代番号で無効化。バックグラウンドでは停止。
- PWAアイコン192／512px、相対`start_url`／`scope`、アプリ専用Service Worker。

## Androidだけでの使い方

1. 公開URLをChromeで開き、画面上部が **MVP 0.5** であることを確認。「更新して再読込」が出たら押してください。旧版のままなら関連タブとアプリをすべて閉じ、開き直します。「動画を選ぶ」でスマホ内の動画を選びます。
2. 初回のAI準備を待つ。通信が必要なのはアプリ・モデル・WASMの取得です。
3. シークまたは±ボタンで選手が見える位置に移動。停止画面に青い番号付き枠が出ます。
4. 対象の枠か番号をタップし、緑の枠を確認。「再生」を押します。
5. 初期設定の「精度優先」では音声なしで解析を待ちながら進みます。連続した映像・音声で確認する場合は「連続再生」を選びます。
6. 最初は「予測保留の上限：2秒」で確認。黄色点線は本人未確認です。取り違えに気付いたらすぐ停止して選び直す。自動停止した場合も、枠から再指定します。重なっている場合は±ボタンで離れた位置に移動します。
7. 問題が起きた直後に「診断ログを保存」。そのJSONを開発者に渡すと直前の判定を調べられます。動画を選び直すとログはリセットされます。
8. Chromeメニューの「ホーム画面に追加」（端末によっては「アプリをインストール」）でPWAとして利用。

まず選手が大きく映る10〜30秒程度の区間から確認してください。重い場合は0.25倍／検出5 fps。動画形式はChromeが再生できるもの（例：MP4 H.264）。HEVC等は端末依存です。別アプリに移ると追跡を停止します。

## プライバシーと長尺動画

`File`を`URL.createObjectURL`で動画要素に渡します。動画全体の`arrayBuffer()`化や全フレーム展開は行いません。前回の縮小グレー画像、現在の解析画像、上限付き軌跡・診断ログを保持し、転送したImageBitmapは閉じます。動画変更時には古いObject URLを破棄します。

動画・画像・外見特徴をネットワークへ送るコード、アクセス解析、外部推論APIはありません。第三者への通信はjsDelivrとGoogleのモデル配信に限ります（ページ配信はGitHub Pages）。Service Workerはアプリ画面用ファイルだけをキャッシュし、動画や他のアプリのキャッシュには触れません。

20〜50分動画を逐次処理する設計ですが、実機の長時間動作・発熱・ブラウザのデコードメモリは未検証です。再読込すると動画選択・追跡結果は消えます。全試合の結果保存は未実装です。

## 現時点の限界

- 同じユニフォーム・交差・小さな人物・遮蔽・ベンチの観客・ぶれで検出失敗や取り違えが起こり得ます。停止判定は保守的ですが、誤追跡ゼロを保証しません。
- 色分布は簡易外見特徴で、高度なRe-ID／背番号認識ではありません。
- Optical Flowは平行移動の補助。予測速度に沿う探索を加えましたが、急な方向転換・ズーム・回転・大きなパン・カット切替には弱く、コートへの射影や安定化は未実装です。
- **黄色い軌跡は画面上の履歴です（黄色点線の枠は未確認の予測）。カメラ移動を含み、実際の走行経路・距離ではありません。**
- 実際の試合動画は今回提供されていないため、連続追跡時間や実動画精度は未検証です。
- 初回モデル取得はオンライン必須。アプリ画面はオフライン起動できますが、モデル／WASMはService Workerで完全保存していないため、オフラインでのAI起動は保証しません。
- 性能が不足する場合、実測検出頻度は設定値より低くなります。数値は実時間あたりの検出回数で、0.5倍再生では動画時間基準の設定値より小さくなります。

## GitHub Pagesの公開設定（スマートフォンで1回だけ）

2026-09-12に利用者がPagesを有効化し、公開ページの表示を確認しました。以下は別の環境で公開する場合の設定です。

1. GitHubのこのリポジトリを開き、Settings → Pages。
2. Build and deployment の Source を **Deploy from a branch** にする。
3. Branchを **main**、フォルダを **/(root)** にしてSave。
4. デプロイ完了後に公開URLを開く。

ビルド不要の静的配信です。`.nojekyll`あり。既存のroot配信を継続します。Pages向けパスはすべて相対指定、Workerも`import.meta.url`を基準に解決します。AIのJS/WASMは同じ固定バージョンの絶対CDN URL、モデルはGoogleの絶対URLです。

更新時は動画確認を終えてアプリと関連タブをすべて閉じ、再度開いてください。新Service Workerは実行中の解析を強制更新しません。更新用ファイルはHTTPキャッシュを再利用せず取得し、新版のキャッシュに旧ファイルが混ざることを防ぎます。

## 開発・検証

Node.js 22以上、外部npm依存なし。

```sh
npm run check
npm test
python -m http.server 8000
```

最後のコマンドは開発者用であり、利用者はスマホだけで利用できます。GitHub Actionsでも構文・回帰テストを実行します。

- `app.js`: 元の動画選択／描画／操作を拡張。1フレームずつWorkerへ転送。
- `detector-worker.js`: MediaPipeと追跡処理。WASMローダーの`importScripts`に合わせClassic Workerを使用。
- `tracker.js`: Kalman、外見比較、曖昧候補排除、疎なOptical Flow。
- `ai-config.js`: JS/WASMバージョンとモデルの一元管理。
- `tests/`: 合成人物による追跡・見失い固定・競合・不連続・既知パン、およびPWAの範囲とパス。

実動画の追跡精度はこれらの単体テストでは検証できません。

2026-09-12の公開確認：GitHub Pagesのページ・JS・Worker・manifest・Service Worker・アイコンはHTTP 200。Workブラウザで動画選択、8秒のテストMP4読込、シーク、再生操作、PWAインストール案内の表示を確認しました。検証用ブラウザはWebGL 2非対応のため、人物検出・連続追跡のブラウザ実動作は未検証です。AI初期化ではWebGL 2とウォームアップ推論を確認し、実行不能なのに準備完了と表示しないようにしました。Android Chromeでの実動画確認が必要です。

2026-09-13のMVP 0.5公開確認：Workブラウザで旧0.4から更新ボタンによる反映、動画選択と8秒MP4の読込、＋1秒シーク、保留上限の変更を確認。診断JSONは単体テストで生成内容を検証しましたが、Workブラウザではダウンロード完了を確認できませんでした。ページ・アプリJS・Worker・manifest・Service Worker・アイコンはHTTP 200。アプリ由来の未処理JavaScriptエラーは確認されませんでした。WorkブラウザのWebGL 2非対応によるAI実行の制約は引き続きあり、実試合での改善度は未検証です。
